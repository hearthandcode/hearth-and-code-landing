# Living Public Ecosystem Prototype

## Local-review boundary

This branch is a review-only public-surface prototype. It adds reader-facing visual language to the Hearth and Exocore routes without changing production, collecting input, rendering private data, or claiming that a local Exocore runtime exists.

## What to review

1. The **Ecosystem Process Rail** on the Hearth page. It moves through Question, Evidence, Review, and Public proof with static HTML fallback and optional keyboard stage selection.
2. The **System Boundary Map** on the Exocore page. It separates the reviewed public web, shared visual conventions, and the proposed local workbench boundary.
3. The visible **Evidence / Inference / Proposal / Open question** labels. They should orient a reader without making the page feel like a compliance form.

## Review prompts

- Does this create a legible public ecosystem rather than a simulated dashboard?
- Does the Exocore page now explain its public and proposed boundaries more clearly?
- Is the process selector useful enough to keep, or would a static narrative be more direct?
- Which single visual primitive should become the next reusable public-surface convention?

## Boundary reminders

- No analytics, forms, cookies, user accounts, or input capture.
- No local paths, private records, runtime state, receipts, provider configuration, or agent controls.
- No merge, deployment, or public release follows from this review branch.
