# Implementation Campaign

> 05 / Portfolio reference

The implementation campaign is the action test. It is the five-step process that every effect passes through before it runs.

## The five steps

1. **Plan** — name the effect, the target, and the scope. The plan is bounded; it does not expand without a new release.
2. **Source** — bind the source and the review state. Every claim in the plan traces to a source that has passed corpus review.
3. **Release** — obtain the explicit human release. The release names the effect and the target; it is not inferred, inherited, or self-issued.
4. **Preflight** — check the scope and the no-touch boundaries. The preflight verifies that the effect does not touch what it was not released to touch.
5. **Receipt** — record what changed, how, and why. The receipt is a bounded process report; it does not authorize the next action.

## What it is not

The implementation campaign is not a pipeline, a workflow engine, or a gate. It is a discipline: every effect is named, sourced, released, checked, and recorded. An effect that has not passed the campaign is a proposal, not a deployment.

## Where it fits

The implementation campaign is the second of two bounded processes. The first is the corpus review (the reading test). Together they form the reading-then-acting cycle.
