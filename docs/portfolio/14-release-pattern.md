# Release Pattern

> 14 / Portfolio reference

The release pattern is the governance discipline that makes every effect inspectable. It is not a workflow engine; it is a named, sourced, human-released action.

## The pattern

Every effect in the Hub follows the same pattern:

1. **Intent** — the agent or the human names the effect, the target, and the scope.
2. **Release** — the human (Scott) issues an explicit release naming the effect and the target. The release is not inferred, inherited, or self-issued.
3. **Receipt** — the effect is recorded: what changed, how, and why. The receipt is a bounded process report; it does not authorize the next action.

## What it prevents

- Silent effects: an effect without a release is not an effect; it is a proposal.
- Self-authorization: the agent does not issue its own release; the release is the human's voice.
- Scope creep: the release names the scope; the agent does not extend the scope.
- Untraceable changes: the receipt records what changed; the receipt is the audit trail.

## Where it fits

The release pattern is the governance layer of the Agentic OS. It composes with the corpus review (the reading test) and the implementation campaign (the action test) to form the reading-then-acting cycle.
